# Long-horizon Automatic Agent: continuation-authority and retry audit

Scope: production Clack lifecycle (not ForgeBoard acceptance), audited against committed base `3543737270a00040a34b4f6a84a344c0f1c99a4a`. This document describes ownership and observable semantics; it is **not** a new native proof or approval to run ForgeBoard.

## Authority inventory

An authority's *creation* and *storage* are separate from an inference's right to **use it now**. `R` = automatic provider-timeout recovery; `P` = bounded conversation preparation/compaction; `C` = next same-logical-Agent coding generation. The `R / P / C` column names what is preserved versus revalidated or replaced.

## Hardening changes and source-demonstrated defects

1. **Ordinary Agent compaction used the wrong authority horizon.** `agent.ts` selected five-extraction-attempt coverage only for `agentRequestFailureRecovery`, although ordinary steps use the same `createConversationCompactor.prepare()` path. Safe-step renewal now uses a shared bounded preparation horizon for *both* ordinary and recovered Agent steps.
2. **The post-compaction inference reused an earlier lease decision.** A valid lease before potentially 600 seconds of preparation need not cover the subsequent 600-second self-hosted native HTTP horizon. At a second, safe boundary *after* preparation and *before* provider dispatch, the Agent repeats genuine exact-tier renewal only when due, rebinds the same model preflight, and refuses proof substitution during provider recovery.
3. **Native-tool verification flight was too coarse.** The endpoint lease is properly exclusive, but previously a simultaneous different profile/tier/config caller received the incumbent flight's result. Calls now coalesce only on the exact verification identity; different verification intent waits for the incumbent to drain, rereads native persisted state and performs its own scoped verification.
4. **Recovery transcript/workspace TOCTOU.** A successful checkpoint comparison could be invalidated during the asynchronous persistence of `phase:dispatched`. The final post-persistence dispatch gate now rechecks transcript, every completed workspace receipt, write checkpoint, complete workspace fingerprint and run/permission/todo/plan/budget owner.
5. **Explicit interrupted-run retry had weaker mutable-owner validation.** Before resuming it now binds the original session model/profile, permission authority, plan/todos and (when workspace exists) the native full-tree fingerprint. It rechecks after persistence and at dispatch; deliberate edits made **before** explicit retry are still possible.
6. **Multi-chunk extraction could inherit a stale mid-preparation lease.** The extractor's total lifetime watchdog covers more than five 120-second provider attempts because native reads, validation and memory commits occur between them. A 15-minute lease cannot cover its full theoretical ceiling. Each *new* extraction provider attempt now calls an optional Agent-owned `beforeModelAttempt` safe-boundary hook before charging or dispatching; the hook obtains genuine same-tier renewal with a 150-second per-attempt horizon when needed. It is awaited with the extractor's cancellation signal, never detached. Failure stops compaction without publishing partial memory or opening an overlapping provider call. The Agent still renews before the overall preparation window and separately before the next coding request.

Two **test-only** baseline mismatches were also corrected to restore broad regression coverage. The model-switch integration fixture now returns the native command's valid *empty* `MemoryView` instead of `null` when historical tool history triggers memory loading. The Qwen native-byte replay tests now construct their request from the **immutable recorded historical prompt and JSON schema**, rather than asserting that today's intentionally updated probe prompt and JSON-schema generation produce identical historical bytes. Neither test change relaxes current production proof checks or alters the historical native-response fixture.

## Retry composition invariants

- The **outer** provider timeout recovery allows one new segment, guarded by the durable same-run checkpoint and `agentRequestRecovery.attempts`; it never regenerates already-completed tool effects.
- The **inner** provider retry wrapper has at most two bounded pre-meaningful-output subattempts within the original 120-second guard; SDK `maxRetries:0` does not provide another retry budget.
- One compaction preparation has at most five total model attempts and one additional invalid-output **or** smaller-prefix timeout retry. Both paths reuse the original evidence; model calls must settle before the next attempt. Native CAS publication is preceded by validation and followed by authoritative reload.
- A calibration renewal obtains a new measured record with exact tier, retained runtime epoch/digest/reasoning, and genuine loaded allocation. It cannot issue a surrogate proof or reset budgets.
- A distinct Agent batch or user-requested retry cannot rewind `SessionRun.startedAt`, `agentRequestRecovery.attempts`, `continuationCount`, tool IDs, or durable writes. Aborted/superseded operations fail closed.

## Explicit boundaries and limitations

- The 15-minute context calibration lease and 24-hour native-tool proof TTL are unchanged. Three separate **real** renewal horizons now apply: **630,000 ms** before potentially long preparation, **150,000 ms** before each individual extraction provider request (including the 120-second bounded model attempt and 30-second safety lead), and **630,000 ms** after preparation before the native HTTP coding guard. Neither check extends any lease by assertion.
- The compaction extractor's overall watchdog still covers non-model work in addition to its five bounded model calls. If an individual native read/validation/commit becomes too slow, the existing extractor deadline or request preflight can still stop the operation. The new per-attempt hook prevents a subsequent extraction from inheriting an expired calibration even if cumulative preparation crossed the initial lease; it does not suppress or extend the extractor watchdog.
- One oversized **protected** tool-result group or immutable requirement can exceed the verified working context; `compaction-protected-budget` must still fail closed. Reducing/truncating completed tool effects without provenance would be incorrect. This was the isolated earlier live verification's separate failure, not a renewed-lease result.
- A native model, runtime, memory or workspace that changes mid-operation is intentionally terminal for that dispatch. This task does not establish ForgeBoard acceptance or production-readiness of all model/server combinations.
- The combined test uses production calibration, preflight, checkpoint, extraction, memory and run-budget *state machines* with deterministic native/provider dependencies. It does **not** establish a live Ollama timeout/recovery run, native Rust filesystem CAS integration in the same test, or a full genuine SDK/Chat UI logical-completion stream. Store-level recovery/permissions and Rust memory behavior have separate tests; no live acceptance was requested or performed.
