### `rFedtJ` — FAILED, missing process-handle wait authority identified

- Source: `src-tauri/target/tf-browser-isolation-acceptance/clack-tf-browser-isolation-rFedtJ/acceptance-verdict.json`. The new event barrier held the native dependent COM work through the sixteen-second watchdog, but the parent still could not select an alive independently verified renderer. `rendererCrashTargetPid=null`, `rendererCrashInjected=false`, `processFailedEvents=0`, and the deferral was completed as synthetic **504** on watchdog, not misrepresented as an actual native crash. Overall **FAILED**.
- The runner opened each original WebView2 child process object with `PROCESS_QUERY_LIMITED_INFORMATION | PROCESS_TERMINATE`, then tried `WaitForSingleObject(original_handle, 0)` to prove its liveness. That HANDLE lacked the Windows standard `SYNCHRONIZE` right, so a real live process could produce `WAIT_FAILED` and be incorrectly skipped. A focused real Win32 regression demonstrated that difference against the current process: query-only HANDLE → `WAIT_FAILED`, same process with `SYNCHRONIZE` → `WAIT_TIMEOUT` (alive). The runner now requests `SYNCHRONIZE` at original capture and treats every unexpected wait status as an explicit error, never as proof of exit or permission to reopen a recycled PID.
