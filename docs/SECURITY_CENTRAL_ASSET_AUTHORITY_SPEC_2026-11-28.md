# Central native asset authority — architecture and acceptance specification

**Date:** 2026-11-28
**Status:** Proposed; documentation only. Implementation and physical acceptance are not claimed.
**Baseline:** maintenance worktree `maintenance/protected-main-quality-20261128`, based on protected-main `dddab1b9c4f035362c754c5111a39e3c209178a4`. Other maintenance edits may be present; this document does not qualify them.
**Owner:** existing TF2 permission/side-effect authority (Contract G), native workspace ownership and consumer-specific existing content authorities. TF13/AR4 receipt integration remains governed by the existing roadmap, not a new receipt database.

## 1. Problem, scope and evidence boundary

The goal is to remove arbitrary filesystem-path access through the local asset delivery surface while preserving legitimate Markdown, chat, editor, audio/video, PDF and preview workflows. This is a bounded read-only delivery design, not a general filesystem sandbox, a replacement for TF2, or a redesign of all native IPC. No blanket shutdown of local previews is authorized.

## 2. Threat model and invariants

Treat model output, Markdown/HTML, document paths and links, renderer request fields, attachment metadata, URL/query/fragment, MIME extensions, remote page content, and workspace filesystem contents as untrusted. A process or collaborator able to change a workspace entry may race validation. A compromised renderer can invoke exposed IPC within its actual Tauri capability set; frontend checks alone are not authority. A fully compromised OS/native process is outside this contract.

- A successful response is derived from a real native owner, an exact allowed file identity, a current read-only grant, a bounded permitted representation and an authorized consumer. No filename-to-URL shortcut grants access.
- A root registered for shell or startup is not an asset grant. No authority transfer across workspace, session, window, consumer, operation, generation or application restart.
- Deny by default on unknown owner, invalid path, uncertain identity, unsupported filesystem or format, expiry, revocation, cancellation, stale generation, missing approval or exhausted resource budget.
- No directory listing, writes, executable launch, network fetch, provider upload, agent attachment, shell reveal or OS external-open capability is implied by a preview grant.
- No secret/Git metadata access via asset authority; no bypass through aliases, HTML, media ranges, external picker, cached URLs, redirect, error details or legacy protocol.
- Revocation stops future delivery and cancels owned pending/active work; bytes already delivered to a renderer cannot be recalled. No claim of post-delivery secrecy from a compromised renderer.

## 3. Native ownership and decision model

Use one native policy implementation shared with TF2 read-path checks. Extract platform-neutral rules and audited platform-specific path/open primitives where needed; preserve TF2 existing operation, approval, cancellation and receipt behavior. TF2 is currently Windows-oriented, so portable implementation must be explicit rather than a permissive fallback. Do not reuse write approvals as reads or change tool policy to make previews succeed.

Extend WorkspaceRegistry/native owner lifecycle to represent an exact selected workspace identity (canonical root, stable root identity and generation) associated with the native window/WebView and an existing session or editor/preview owner. Workspace selection and external-file approval must be tied to native-observed user intent, not the renderer supplying an arbitrary root or actor string. A trusted user-open/restore path needs explicit validation; restored workspace membership does not restore asset grants. Bind editor/Markdown consumers with no chat session to their real workspace/view owner rather than inventing a global session. Switching away invalidates the relevant previous ownership; multiple legitimately open owners remain independent. Reopening the same path creates a new generation. Native window labels must come from invocation context and be paired with an instance/generation, not trusted as strings supplied by callers.

The existing broad registry bootstrap and `workspace_authorize` IPC cannot by themselves prove a specific user decision or current session. Extend the same registry to distinguish legacy root membership from active selected ownership. Do not remove legitimate terminal root behavior as an incidental change; never elevate legacy root membership into asset authority. If current lifecycle/capability plumbing cannot establish this proof, the affected grant is unsupported until corrected.

### Native contract (proposed names, not existing APIs)

| Operation | Input and native behavior |
| --- | --- |
| prepare_asset | Typed consumer purpose and candidate reference, owner identity resolved natively, current document identity for relative links. Validate policy, open verified file and determine representation/caps. No raw path URL returned. |
| approve_external_asset | Existing native user-dialog/open authority selects exactly one file and binds result to live owner and consumer. Cancel/deny has no grant side effect. No renderer boolean or path echo accepted as approval. |
| issue/redeem asset | Opaque random handle (at least 192 bits from OS CSPRNG); native-only record binds owner instance, workspace/session/view generation, exact file identity, consumer, MIME, byte budget, deadline, cancellation and optional existing approval reference. Redemption checks all bindings before bytes. |
| release/revoke | Existing owner cancellation/closure hooks invalidate pending and live grants and streams. Explicit release is idempotent, scoped and cannot affect unrelated owners. |

Use TF2-style bounded pending/active lifecycle and native monotonic deadlines. The asset delivery record is ephemeral execution state within the existing authority, not a new permissions engine, persisted allowlist, approval database or alternative tool identity. Keep permission decisions separate from transport bookkeeping. Grant IDs are unguessable capabilities but never the only authorization check. Only native-issued asset descriptors enter trusted consumer components; do not serialize bearer URLs into chat history, model prompts, Markdown, settings, telemetry or clipboard by default. If the scheme handler cannot obtain trustworthy requesting WebView identity or distinguish an embedded remote frame on a platform, do not assume headers or a claimed owner are sufficient; use the bounded IPC delivery alternative below or isolate the renderer/view with a separately verified origin and native ownership.

External user files: allow a read-only exact file explicitly selected by a real native picker or OS-owned confirmation, with visible purpose/size/type and originating owner. No parent root registration, glob, sibling read, implicit directory approval, inferred approval from Markdown, agent/tool argument or drag payload. Drag/drop and OS open events require native provenance and explicit UX review where ambiguity exists. Existing protected secret/metadata denials are not overridden by picker selection for preview; separate deliberate export/import policy, if needed, is outside this spec. Replacement, rename or path identity change requires fresh authorization, not a silent follow. Preserve externally opened ordinary images/media/PDF when explicitly selected. Native dialog cancellation and stale results must fail closed.

## 4. Canonical path and opened-object confinement

Perform decoding once at the typed boundary. Reject malformed escapes, NUL/control chars, ambiguous separators, unsupported URI schemes, double-encoded aliases and unexpected query/fragment. Separate display suffix from path; do not permit suffix to change the native resource. Never reinterpret a URL as an OS path in the serving endpoint. Relative Markdown paths resolve against an authorized document parent (root-relative Markdown syntax against the selected root). Legitimate dot/parent syntax may be normalized only within that root without climbing above it, before the shared strict TF2 lexical validator. Native revalidation remains mandatory; renderer normalization is not evidence. An absolute path may be considered only under exact selected workspace or exact external approval.

1. Establish trusted selected root and its native identity, not just a prefix string. For external grant establish the exact picker-selected object and parent chain. Reject unsupported or redirected root. Resolve path components without following links. Inspect every ancestor and leaf, require existing regular files, deny directories, device nodes, FIFOs, sockets, special files, missing components, inaccessible metadata, forbidden secret/Git components and unresolved aliases.
2. Apply TF2 lexical/secret policy to original and resolved names; reject Windows UNC/device/verbatim input, drive-relative paths, ADS, reserved device names, trailing-dot/space aliases and ambiguous short-name aliases. Use actual filesystem case semantics, component boundaries and stable identities; do not implement case handling with universal lowercasing. On POSIX reject symlinks, special files and escape across mount/bind boundaries unless explicitly supported and proven; deny multiply-linked files where provenance cannot be established (initial policy: reject hardlinks with link count greater than one). Windows reject all reparse points including junctions and volume mount points, not merely symlink leaves.
3. Open with race-resistant native primitives, then verify the same opened object and read only that handle. On Linux use directory-relative no-follow opens, preferably openat2 with beneath/no-symlink/no-magic-link/no-cross-device restrictions where supported; audited component-by-component directory FD fallback only if equivalent guarantees hold. On macOS use directory-relative no-follow opens, fstat identities and root/parent generation checks; prove rename/mount and case/normalization cases. On Windows use handle-relative or equivalently race-resistant opens, reparse-aware flags and handle metadata (volume/file ID, type, link count, final path), verify root/ancestor identity and containment; ordinary canonicalize-then-open or a leaf-only no-follow flag is insufficient. If a platform cannot provide the required identity/race guarantee, deny that case and document unsupported scope.
4. Bind grant to opened object identity and validated ancestry/root generation. For each redemption/range recheck owner, deadline, cancellation, current path/root binding and file metadata. Serve from the same owned read handle or reopen only through the identical verified procedure and require identity match. Reject replacement, truncation/growth, type change or rename invalidating the binding. Snapshot bounded small files when appropriate; for streaming, verify bounded ranges and detect concurrent modification. Do not claim immutable bytes from metadata alone: if exact immutable content is needed, use the existing content snapshot/attachment authority or a bounded private immutable snapshot. No unverified bytes on conflict; stop future streaming, report uncertainty for bytes previously emitted.
5. Never use canonical cache as final proof. Validate before admission, at open/redemption and at bounded chunk boundaries. Coordinate cancellation with admission and response emission; no untracked interval between pending and active. Avoid holding global lock during disk I/O; use per-owner generation and cancellation state with final compare before emission.

Initial unsupported network shares, alternate streams, special devices, cross-volume links and ambiguous mounts fail closed. Do not weaken rules to make fixtures pass; genuine compatibility requests need separate documented policy decisions.

## 5. Delivery boundary and bounds

Preferred transport: native-owned opaque asset endpoint, with no raw filesystem path in the URL, no generic file serving, no redirects, and native authorization on every request including cache/range retries. Determine actual Tauri/Wry scheme-to-origin mapping and trusted request context per platform before choosing API. Do not assume a custom scheme is secure merely because it is custom.

Alternative for bounded small images/doc previews: native owner-scoped IPC reads from verified handle into bounded bytes, then consumer-owned blob URL with deterministic revoke. No public loopback server; no browser CORS workaround; no renderer-exposed arbitrary file reader. Large media/PDF need genuinely scoped bounded range delivery or an explicit supported-format limitation, not an unlimited IPC buffer. A private immutable spool if needed must be owned, capped and cleaned by native authority; never expose a wildcard spool directory to every WebView.

The following are **proposed initial conservative limits**, subject to measured UX and resource review before implementation. They are not measured platform requirements or existing settings.

| Budget | Initial ceiling / rule |
| --- | --- |
| Grant lifetime | 60 seconds monotonic, no sliding extension by HTTP GET. Trusted visible owner may request a fresh grant after revalidation; no background renewal after closure. |
| Grant/stream count | 32 live grants per owner, 128 globally; 4 active reads per owner, 16 globally; bounded queue or explicit busy denial. |
| Native path/request | 4096 UTF-8 bytes candidate, bounded component count (128), bounded URL/header parsing; reject excess before I/O. |
| Raster image/thumbnail | 16 MiB encoded, 32 megapixels, dimensions at most 8192 each; bounded decoder memory/frames (animated images: 256 frames and 128 megapixels cumulative). Reject bombs/malformed dimensions before unbounded decode. |
| SVG | No raw active SVG document or SVG-in-frame; bounded safe rasterization with external references, scripting, fonts/resources and XML entity expansion disabled, or explicit unsupported preview. Preserve explicit external-open separately. |
| PDF | 64 MiB encoded, 500 pages for embedded preview, bounded parser/render memory and page dimensions; isolated inert viewer, no active JS/actions/embedded files/external resources. Oversize/unsupported safe viewer reports blocked; no fallback to raw active PDF frame. |
| Audio/video | 512 MiB verified regular file; range delivery, max 4 MiB per response/chunk and 2 GiB cumulative per grant (including repeats); fixed overall and idle deadlines, no unbounded full-file load. Require measured seeking/playback on each platform. |
| Other content | No HTML/JS/CSS/executable/archive/raw text delivery through asset endpoint. Existing text editor path remains separate. Unknown MIME, mismatch, polyglot or unsupported codec denied. |
| Resource lifecycle | Bounded handles, buffers, response counts (1024 per grant), cleanup on error/expiry/cancel and native shutdown. Initial aggregate native buffered bytes cap 64 MiB; reserve before allocation. |

Native content classification must use verified bytes/structure and allowed media types, not caller/extension alone; use a maintained bounded parser/decoder, not bespoke unsafe sniffing. For allowed type provide exact Content-Type, nosniff, no-store/private cache policy, no permissive CORS, no redirects or response body on denial, and restrictive applicable CSP/frame controls. Test actual engine support for headers; headers are defense-in-depth, not the primary grant decision. GET/HEAD only (HEAD requires same grant); deny OPTIONS or unsupported methods unless a narrowly justified platform transport requirement is proven. Validate single byte ranges, overflow, start/end/length and cumulative accounting; reject malformed or multi-range requests, 416 without disclosing unauthorized size. Authorize before any size/MIME disclosure. Bound error timing and avoid distinguishing nonexistent from inaccessible to untrusted callers. No service-worker or disk caching of bearer responses; verify WebView behavior, not just headers. Disable navigations to opaque asset endpoints except explicitly safe viewer use.

## 6. Lifecycle, concurrency and UI

State transitions: requested -> validated/opened -> optional native approval -> granted -> active reads -> released/expired/revoked/failed. Denial/cancel terminal states cannot become granted through late callback. Linearize revocation before accepting further reads; pending-to-active transition must be atomic as in TF2. At closure, bump generation and detach grants/streams, abort in-flight I/O and drop handles/buffers/snapshots; no response emission after native revocation acknowledgement. If engine/network buffering already handed bytes to WebView, record that boundary honestly. Owner-specific close/cancel does not interrupt independent owner B. Restart starts with empty grants. Explicitly hook workspace switch/close, chat session close/delete/cancel, editor tab/preview disposal, native window/WebView destroy/navigation/crash, approval dialog close, application shutdown and owner generation change. A hidden but legitimately open preview may be released and reissued by its owner; no silent renewal for canceled work.

UI: show loading, blocked/unsupported, expired/reopen and cancelled states, without exposing sensitive paths or raw error details. Retry only by current owner revalidation; never fall back to raw path URL, generic file IPC, remote fetch or data URL. Clear element src, pause/reset media, detach PDF frame and revoke object URLs on closure/switch, including late async callbacks. Bytes already decoded/displayed cannot be erased from a malicious renderer; native revocation plus honest UI cleanup are distinct guarantees.

If intermediate builds retain wildcard, mark security closure incomplete; do not release or describe them as remediated. Do not simply flip assetProtocol off before replacement, and never restore wildcard as a rollback shortcut after security acceptance. Rollback is an explicitly reviewed prior version with its known unresolved exposure, or a scoped preview disable for affected unsupported formats while safe routes stay available.

Record exact binary hash/source commit, OS/build, Tauri/Wry/WebView engine/version, packaged security config, architecture, test runner identity, UTC timestamps and test fixture content hashes. Windows WebView2, macOS WKWebView and Linux WebKitGTK each require independent positive and negative physical evidence on supported release targets. Use a controlled local fixture origin for remote-frame tests and observe traffic only within owned test environment.

A broken image alone does not prove denial; a denied IPC call alone does not prove no legacy protocol bypass. ## 9. Evidence and release gate

Per case retain immutable case ID, exact commit and artifact digest, fixture manifest hashes, OS/engine metadata, owner generation pseudonyms, expected/observed result, sanitized native decision reason, authorized byte count, independent rendered/response hash or negative observation, cancellation timing and cleanup counters. Use existing acceptance/effect trace conventions and owner-scoped evidence directories. Do not add persistent authorization history, bearer tokens, raw private data or competing receipt ledger. A read receipt means bytes served under a grant, not proof that a human viewed them. A denial receipt means denied attempt, not proof that all other paths are safe.

Gate criteria: no unauthorized canary bytes in any required case; no raw wildcard bypass; all supported positive cases pass; exact owner/revocation/resource invariants proven; no weakened existing mandatory checks; independent source review verifies every consumer migrated and scope cannot widen at runtime. Cross-platform unavailable/unsupported cases remain explicitly blocked or NOT_RUN, not inferred pass. Report residual risk and compatibility limits by format/platform. If an actual negative case produces bytes, stop qualification, preserve controlled evidence and investigate; do not claim real-user disclosure from a synthetic fixture. Do not publish sensitive proof artifacts. No production rollout or release acceptance based solely on this document.

## 10. Implementation boundaries and open decisions

- Native owner: existing WorkspaceRegistry and TF2 shared path/policy primitives; review exact capability/invocation context, active workspace/session/view generation and external picker trust. Transport choice (custom scheme vs owner-scoped IPC) depends on trustworthy per-request origin/owner context and range support, proven on all three engines.
- Platform confinement: choose audited handle primitives and establish race semantics, mount policy and content snapshot strategy; unsupported primitives fail closed. Existing TF2 preflight checks are a starting point, not a verified race-resistant primitive.
- Consumer owners: Markdown, chat attachment/rendering, editor/media/PDF and workspace/window lifecycle owners each migrate their own surface; central policy must be called rather than copied into TypeScript. Verify PDF/SVG safe renderer feasibility, resource budgets and codec support before declaring full compatibility.
- Review existing generic filesystem IPC and Tauri capability/plugin scopes for confused-deputy paths; open separate bounded work if broader native read authority can bypass this contract. Scope this milestone honestly: local asset delivery, not a claim of complete sandboxing against arbitrary native execution.
- Proposed numerical caps, supported representations, native API names and transport are design decisions for review. No runtime source or CI changes are made by this document; no physical or offline product tests were executed for it.
