## Test ownership

The old `vitest run` command imported Node's `node:test` suites, yielding "No test suite found" instead of proper framework-level results. The new `scripts/test-execution-contract.mjs` discovers the direct `scripts/*.test.mjs` runner from its explicit imports, rejects ambiguous files, and runs each with the appropriate runner. Both exit statuses count. The complete `npm test` command runs all suites including evidence-dependent tests and fails when required evidence is absent. `npm run test:portable` is the hosted deterministic CI contract; `npm run test:evidence` runs the separately mandatory evidence checks with real inputs. A portable success must never be reported as full evidence/physical acceptance.

The first independent Node execution of 23 suite files recorded 126 passes, six failed evidence-dependent Muse tests and one LM11 suite-load error due to a missing authentic T15 report. It revealed real coverage previously hidden by framework mismatch. No such failure is waived or replaced by synthetic evidence.

The evidence command preserves the acceptance assertions and failure behavior. Its explicit inventory is: eight Muse preserved-settings replay tests, two hosted-egress historical-report hash checks requiring the original frozen native reports, one LM11 real-store selector test requiring the independently authenticated BEFORE inventory, three LM11 attributable-policy report tests, three Muse host-source tests and three evidence-dependent Muse crash-only tests. The hosted-egress checks separate the runnable guard assertions from the historical before/after hash assertions without removing either. The CI log and summary explicitly identify the twenty unexecuted evidence tests; absent evidence cannot establish release or physical readiness. No production Store, credentials, or historical private evidence is copied to hosted CI.

Only draft pull requests use the portable contract. Non-draft pull requests, protected-main pushes and explicit-source dispatches retain the complete `npm test` gate; ready-for-review and converted-to-draft events trigger fresh CI.
