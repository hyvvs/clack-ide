## Production path and source of authority

`bash_run` still exclusively executes through existing `checkShellCommand` and `native.shellSessionRun` (Tauri `shell_session_run`, with existing tool approvals and workspace/cwd authorization). Optional `verify_todo_id` supplies an **explicit accepted same-session Todo identity**, and `verification_purpose` records the check's intended purpose. The native result (command, exit code or unavailable exit, timeout, observed errors) is recorded by the tool *after* the native call, through `useTodosStore.recordNativeCheck`, persisted alongside the existing accepted Todos in `terax-ai-todos.json`. Receipts carry a unique local evidence ID returned with the native tool output, session/workspace/run start, user-turn count, command, bounded purpose, start/end time, status, source witnesses and qualification. `todo_write` cannot submit receipts; textual pseudo-tools remain inert. There is no second executor, task state store or permission flow. Permission rejection before dispatch may only appear in the original tool/approval record; never relabel absence of an executed check as a pass.

The added Rust command `agent_workspace_fingerprint` is **read-only**, calls existing `authorize_spawn_cwd`, requires a local authorized root, and emits a SHA-256 of the canonical root plus a deterministic walk of every directory and file including hidden/ignored/untracked entries and their content (excluding `.git` metadata). It refuses symlinks/junctions, unreadable or unsupported entries, non-UTF8 paths, more than **2,048** entries, more than **32 MiB** of source bytes, unavailable/foreign roots and WSL/remote roots. A Git HEAD alone never qualifies. Before/after snapshots must match; after reopening, the R3a panel samples the current root and compares the exact persisted digest with the original. While open, it resamples at 30-second intervals and on window focus when there are native receipts. **Freshness is only as of the last observation**; races, environmental dependencies outside the root, Git hooks/metadata, large real repositories and transient changes are not independently ruled out. An unavailable witness means *unknown freshness*, not a verified current result.

Existing `Todo` status and persistence now support explicit `supersedesIds` plan relationships, with separate historical `superseded` flags. `reconcileTodos` preserves omitted obligations, retained check receipts and unrelated outstanding work; rejects unknown replacements, reuse of superseded IDs and changing a Todo's title/description in place; caps evidence and plan size. Thus an accepted plan can represent `50 → 25` and subsequent `25 → 10` without reviving 50. A `cancelled` Todo remains distinct from superseded. **A model's supplied supersession relationship is an accepted structured plan claim, not a semantic interpretation or independently verified user correction**: reconciliation is not automatic when no new explicit accepted plan exists. The exact corrective user message remains in the persisted transcript and R3a unmatched-instruction report until reconciled.

The existing `RunObligationStatus` reports associated native checks as passed, failed, timed out, blocked/not-started, or stale/unknown/current-source-check, alongside historical transcript checks, accepted Todo claims, actual terminal reason and continuation availability. Native check results establish **the recorded command's observed result at the sampled workspace state only**. An arbitrary user/model-selected check cannot establish a particular application requirement's semantics: these checks deliberately **do not** promote an arbitrary Todo to `verified-complete`. R3a's separately injected synthetic proof contract is still not a live app proof producer. The application remains unverified unless stricter task-specific, independent acceptance evidence exists.
