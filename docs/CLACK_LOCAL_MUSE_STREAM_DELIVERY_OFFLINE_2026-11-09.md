### Offline PID-scoped probe hardening (2026-11-09; NOT live-qualified)

`scripts/local-muse-tcp.bt` now probes **only** `tcp_sendmsg` entry/return in the exact positional Ollama **thread-group PID** (`pid == $1`), and only for accepted IPv4 loopback sockets with **both** local and peer addresses `127.0.0.1`, the verified server source port (`skc_num == $2`), and a nonzero destination port. SSH processes and their port-22 encrypted sockets are **excluded**. No `comm`-only check, SSH probe or generic `tcp_recvmsg` probe remains. The source is intentionally limited to **little-endian Linux** and **the verified 127.0.0.1:11434 listener**, not arbitrary TCP/IPv6/remote interfaces. If Ollama changes its binding, **fail closed** and request separate review; do not widen the probe to make it attach.

The new `scripts/local-muse-tcp-session.py` is a **Linux-only root-operated supervisor**. Before attachment and every second, it checks `/proc/<PID>/exe`, exact `ollama serve` command, service UID, `/proc/<PID>/stat` start ticks (PID reuse), and the unique TCP listener inode at `127.0.0.1:11434` owned via `/proc/<PID>/fd`. Missing, ambiguous or changed identity aborts source completeness. Arguments permit **1–1800 seconds maximum**; at the deadline minus a five-second grace reservation the supervisor sends SIGINT **only** to its new tracer process group, and sends SIGKILL at the absolute 1800-second hard deadline if necessary. Linux parent-death signaling kills the tracer if the supervisor itself dies. No process is signaled in Ollama. An early administrator SIGINT/SIGTERM stops the same owned tracer group.

Only numeric `TCPMETA attempt|send` records and the mandatory terminal `TCPSESSION complete|partial <attempts> <returns> <pending> <reported-or-inferred-lost> <duration-ms>` are emitted on supervisor stdout. Raw kernel socket pointer strings are replaced with fresh per-session numeric HMAC pseudonyms **in the supervisor's private memory**, then re-pseudonymized by the existing importer; neither pointer nor key is persisted. Source stdout/stderr are separately bounded to **8 MiB / 64 KiB**. Probe startup must emit `TCPREADY <pid> <port>` and the `END` hook must emit `TCPSTAT <attempts> <returns>`; every printed attempt/return and in-flight `(tid,socket)` pair is checked against these counters. Missing startup/END, count mismatch, overlapping thread writes, nonzero reported loss, unknown stderr, scope mismatch, overflow, lost listener, broken execution or abnormal shutdown produces `TCPSESSION partial` (or **no terminal** if the process itself died). **Never report that an unfinished attempt failed or blocked**; missing returns are `pending-or-telemetry-lost`.

`import-kernel` must see exactly one final `TCPSESSION` **at EOF**, independently check its counts, and store a `collector/shutdown` observation. Detected source loss additionally becomes `collector/event-loss`, and any partial/missing/extra terminal output becomes a failed shutdown observation. A live run must start the journal with **`serve <empty-root> <run-id> --require-kernel`**; `/v1/finish` then rejects a missing, failed or duplicated kernel completion even if other collectors succeeded. `/v1/status` exposes `kernelCompletions` and `sourceFailed`. Journal sealing still demands zero loss, zero active uploads and explicit operator acknowledgment of all other sources. A `collector-flush-only` receipt is **not** a host-level eBPF certification or provider delivery proof.
