## Installation prerequisites and current capability detection

**This checkpoint installed and executed no OS probes.** The read-only capability inspection of the approved Linux Ollama host (`7.3.1-1-cachyos`, 2026-11-09) found `/usr/bin/ss`, `/usr/bin/bpftool` and `journalctl`, **no installed `bpftrace` binary**, and `kernel.unprivileged_bpf_disabled=2`. Attaching a kernel probe therefore requires separately authorized operator installation and appropriate root / `CAP_BPF` and `CAP_PERFMON` privileges, plus applicable kernel BTF/probe symbols and a successful probe-only privilege check. No assumption of permissions, socket layout, kernel probe compatibility, or actual egress visibility is warranted from this offline code. Do **not** enable ptrace, debug response-body logging, a traffic interception proxy or service restarts as a substitute.

For read-only **local** capability reporting, use `node scripts/local-muse-delivery-cli.mjs capabilities`. This reports prerequisites as `unverified` until an authorized live diagnostic actually confirms them. On Windows, `Get-NetTCPConnection` exposes endpoint state/PID only, not byte counters; reliable local TCP bytes would require separately approved metadata-only ETW/WFP instrumentation, not silently fabricated counters. Never change Ollama service configuration, model settings or native transport rules to activate a collector.

**Kernel probe semantics:** `tcp_sendmsg` entry is a queued-write *attempt*, return is kernel-accepted bytes or a negative failure; the probe does not inspect/capture the data pointer, HTTP contents or `sk_buff` payload. Kernel socket address/pointer appears only in transient probe stdout; `local-muse-delivery-sidecar.mjs` HMACs it with an ephemeral run key before accepting/persisting any row. Linux `ss` counters (`bytes_sent`, `bytes_acked`, `bytes_received`, `bytes_retrans`) are socket-wide cumulative **TCP** counters. They may include unrelated connections and retransmission, and never independently establish application-level reads. TCP ACK is not downstream userspace `read`. The BPF tracepoint cannot prove Ollama's Go HTTP handler completed an application write, and tracer ring buffer loss remains an **unmeasured source gap** unless an authorized run deploys additional loss counters.

### Remaining live-observability limitations

The Linux BPF source has not been compiled/attached on the actual host, and no authorized local-Windows packet/ETW metadata collector is installed. Reqwest currently does not expose a kernel socket ID; the SSH process does not expose per-channel request identity; Windows user-mode TCP snapshots lack byte accounting; and kernel `tcp_sendmsg` success is not proof of downstream delivery. Journalctl generation counters have no HTTP socket-write semantics. Collector queue loss is counted when observable, but BPF event-buffer loss, failed Tauri `emit`, remote SSH output interruption, process crash before shutdown, and OS clock drift between anchors may remain unobservable. Therefore an **empty interval at any boundary is not proof** that Ollama stopped generating or sending, or that SSH/Clack consumed anything.
