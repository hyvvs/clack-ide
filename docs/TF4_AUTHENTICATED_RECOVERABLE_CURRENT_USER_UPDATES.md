# Authenticated, recoverable current-user desktop updates (TF4 reusable procedure)

**Status:** Demonstrated on Windows 26 November 2026, not a general-purpose unattended updater and **not** browser/privacy consent. Follow this protocol for subsequent CLACK milestones only after separately approving that milestone's actual source, executable, rollback and installation scope. A completed transaction or scheduled task is never replayable.

## Repeatable *new milestone* procedure

1. **Establish immutable provenance.** On the isolated feature branch verify the exact commit, CI, pinned optimized host, original `clack.exe`, NSIS-extracted `clack.exe` and installer SHA-256. Independently compare the staged and packaged host byte-for-byte and account for the exact documented Tauri NSIS marker change (`UNK` to `NSS`); never assume a compiled app's hash is the installed NSIS app's hash. Retain an immutable per-candidate manifest. Validate install scope is the exact approved current-user `%LOCALAPPDATA%\Clack` path, not the repo, main, stashes or user profiles.
2. **Identify independent controller.** With the current installed app still running, establish through an authenticated *fresh* connector call that the controller is independently owned (not a descendant of CLACK), can execute PowerShell commands after target exit and has permission for the Windows task. Record parent PID/process identity but do not treat PID alone as durable identity. If independence cannot be demonstrated, **do not close CLACK**.
3. **Archive only recoverable binaries.** Before change, hash and archive exactly the old four installed program files: `clack.exe`, the original root `clack-browser-host.exe` (if present), `tf4-native-host\clack-browser-host.exe` and `uninstall.exe`. Use an allowlist and reject reparse points/path escape. Preserve file names, relative paths, sizes and SHA-256. Do **not** copy credentials, keyrings, appdata/session data or secrets. Prefer separate backup on user-approved disk; preserve older backup and receipts.
4. **Construct a fresh bounded one-shot transaction.** Derive a **new reviewed script**, distinct transaction directory, randomly generated nonce, task name, expected old/new hashes and exact old-process identity. Require `Preflight` (side-effect-free) and `Rehearse` against a disposable copy of those four files; both must pass before `Execute`. Refuse any pre-existing phase/ack/terminal marker, missing file, bad hash, unexpected process or unexpected symlink/reparse point. No broad cleanup/deletion.
5. **Delegate to a separate interactive current-user Windows Task Scheduler process.** The task, not the exiting app, owns the transaction. It first verifies the current original app/window and independently running controller, then calls `CloseMainWindow()` and waits a bounded period; **never force-kill the original user app**. Once absent, atomically publish a `WAIT_AUTHENTICATED_CONNECTOR_POST_TARGET_EXIT` JSON marker with immutable source/installer SHA and nonce.
6. **Authenticate after exit.** In a fresh successful connector call independently recheck actual original-process absence, controller identity/parent independence, marker fields, transaction uniqueness, task process/running state, and that an ack does not already exist. Only then write `authenticated-connector-reentry.json` with matching nonce/source/old PID/controller PID, via exclusive `CreateNew` and `Flush(true)`. This is controller recovery authorization, **not an OS privacy/browser security decision**. The scheduler verifies that attestation again and refuses late/mismatched/duplicate replies.
7. **Install and verify or restore.** Run the pre-pinned installer from the independent task with bounded wait and exact exit-code check. Independently hash installed `clack.exe` and pinned host against **extracted NSIS** predictions; verify no surprising CLACK process, then launch a single installed CLACK and check executable path, live SHA, responsive HWND and workspace restoration. On missed ack, relaunch unchanged old app. On failure after installer attempt, use only the four archived binaries to restore and rehash, then relaunch; report rollback failure without blindly retrying.
8. **Write immutable, classification-safe terminal evidence.** Write once with end state, phase/event trace, actual installer/app/host SHA, app PID and readiness, rollback status, old archives preserved, separate native browser consent status and E2E status. Fresh independent connector rehash must agree. Never credit a prepared request, dispatched action or terminal install as a human-approved browser operation or a verified external network effect.
9. **Prevent future replay.** Export the completed task XML for evidence, disable the completed scheduled task and verify disabled state; do not delete it or re-run its previously consumed script. Preserve rollback and all historical source-specific evidence. Continue current application acceptance on the installed hash; keep protected main, safety stashes and release PR untouched.

## Stop conditions / authority boundaries

Stop safely if the controller is coupled to CLACK, the old app refuses graceful exit, installed or archive hashes differ, task/phase/nonce/ack identity is ambiguous, a target path is a reparse point, a competing CLACK process exists, or a rollback cannot be verified. Do not claim success on a scheduling acknowledgment alone. A user has to decide each **actual Windows privacy/security per-operation consent dialog**; no connector, scheduler, UIAutomation or test surrogate may click it or pre-fill approval. Keep unaccepted model-native browser capability disabled. Package/update success **does not satisfy** TF4's independent 13 canonical acceptance gates, seventeen-step installed E2E, hosted-effect oracle, or final Product-wide UI/UX Polish & Acceptance.

## Future milestone applicability

The method is reusable; its literal one-shot script is not. Each milestone needs fresh source-scoped hashes, signed-off candidate, independent old binary backup, new ownership/nonce/transaction/task, successful disposable rollback rehearsal, independently observed controller survival and post-install re-verification. Capture OS/WebView2/CPU/memory readiness separately for performance: elapsed installer-to-window proxies are not equivalent to process-cold stopwatch times.
